## Kontrola hotových úkolů

Úvod 3 minuty: připomeň tři cíle workshopu a potvrď, že dnes hodnotíme hotové pokusy. Každý má přibližně dvě minuty na výsledek a hlavní otázku. U 9 lidí zabere kolo 18 minut, poslední 4 minuty patří společným tématům.

- Osobní podstránka: dosavadní využití AI a formulář Můj první pracovní pokus včetně vstupů, hranic a vlastní kontroly.

- Chat a Work: co účastník zkusil, jak se lišil výstup a který režim by příště zvolil.

- Vlastní plugin nebo skill: účel, jeden konkrétní výsledek a co při testu nefungovalo.

- Automatizace: nastavený čas, dostupné zdroje, skutečný výsledek posledního běhu a případný problém.

Výstup kola: u každého člověka zachytit zkušenost, jednu otevřenou otázku a případný další krok. Pokud něco nefunguje, stručně pojmenuj příčinu nebo postup ověření. Individuální dokončování nepřesouvej do společného bloku.

### První živý dotaz

```text
Read-only question about Xerox France E-invoicing and E-reporting.

First read How to Work with This Space:
https://chatgpt.com/space/page_5e555369c93481a499861a09ad54d169

Question: [question, relevant process or system, and status date if applicable]
Answer format: [short explanation or source-backed comparison]

Answer in English in this chat only. Do not create, edit, delete, move or update pages, files, archives, logs, instructions or schedules. Cite the relevant page or original source and its location. Distinguish documented facts, inference and missing evidence. If the original SharePoint file is inaccessible, say what could not be verified. A question does not authorise changes.
```

Při ověření otevři konkrétní zdroj. Porovnej věcný obsah, datum a verzi. Potom polož předem připravenou otázku, pro kterou zdroj odpověď neobsahuje. Ukaž, jak se správně přizná chybějící informace.

### Krátký pracovní výstup

```text
Read How to Work with This Space first. From the available meeting record [TITLE OR LINK], draft open questions for the next meeting. Write in English. Cite the source for each question. Include an owner only if the record names one. Do not invent owners or dates. Return the draft in this chat only. Do not edit pages, files, archives, logs or schedules.
```

Zkontroluj výstup, doplň jen skutečně dohodnuté informace a ukaž, kde bude uložen. Zápis provede lektor nebo pověřený správce na určené cvičné stránce. Platná projektová rozhodnutí zůstávají samostatně označená.

## Pravidla a cvičení v prostoru

### Pravidla pro nácvik

- Přehled projektu určuje účel, správce, platné zdroje a místo pro aktuální výstupy.

- Společné pokyny mění správce. Návrh změny pravidel člen týmu předá správci.

- Jedno vlákno řeší jedno téma. Vlastní pokusy vznikají v osobním projektu pod firemním účtem.

- Do společného prostoru patří zkontrolovaný ucelený výstup. Návrh označ jako návrh a rozhodnutí jen jako skutečně potvrzené rozhodnutí.

- Výstup má autora, verzi, datum a zdroje. Další krok má vlastníka a termín, pokud byly dohodnuty.

- Oprávnění k prostoru, souborům a připojeným aplikacím se ověřují zvlášť. Text pokynů sám přístupy nenastavuje.

Vycházíme z desater verze 0.3 použitých v podkladech z 11. 11. 2026; jejich tehdejší stav byl návrh k internímu schválení. Před workshopem ověř aktuální stav. Pro workshop správce potvrdí konkrétní pravidla nácviku. Materiál je nepředstavuje jako schválenou firemní směrnici.

### Krátký pokus každého účastníka

1. Otevře přehled projektu a vybere si jeden dostupný podklad.

2. Zeptá se na jednu konkrétní věc a vyžádá si přesný zdroj.

3. Otevře uvedenou stránku nebo soubor a ověří alespoň jedno tvrzení.

4. Sdělí, co zjistil, o který zdroj se opřel a co zůstalo nejasné.

### Prompt pro uložení ověřeného výsledku

```text
Update the Xerox France E-invoicing and E-reporting documentation.

First read How to Work with This Space:
https://chatgpt.com/space/page_5e555369c93481a499861a09ad54d169

Human requester: [full name]
Target page and section: [exact link and section]
Requested change and reason: [exact change]
Supporting evidence: [source links and locations or approved information]

Use English. Edit only the requested ChatGPT documentation. Do not modify SharePoint files. Preserve unrelated content and the agreed structure. Ask if the target, evidence, conflict or requester identity is unclear.

Before replacing or deleting information, create a before-change snapshot under 12.1 Archive, preserving the exact previous text, links and version. Record the page, capture time, requester, actual editor and reason. Read back and verify the archive before the live change.

Apply the supported change, increment the page version and append Page Updated records to every changed page and Project Home. Record the human requester and assistant separately, Europe/Prague date and time, change reference, summary, evidence and the direct archive link. Preserve previous entries. For wholly new content, state that there is no previous content to replace. Update the Archive index and any affected navigation.

Read back the changes and archive links. If any step fails, report the actual partial state. Return the changed-page links, archive link and change reference.
```

Dokončení druhé části: každý se orientuje v přehledu, ověří odpověď ve zdroji a ví, kdo spravuje pokyny a kde má být aktuální výstup. Nevyžaduj, aby všichni zapisovali do stejné projektové stránky současně.

## GitHub v praxi

| Čas | Délka | Průběh |
| --- | --- | --- |
| 10:50–10:58 | 8 min | Git, GitHub, repozitář, větev, commit, pull request a sloučení |
| 10:58–11:10 | 12 min | Lektorská ukázka celého postupu na úkolu 00 |
| 11:10–11:35 | 25 min | Každý čte zadání, připraví vlastní větev, změnu, commit a pull request |
| 11:35–11:45 | 10 min | Kolega kontroluje diff a kritéria, autor případně doplní změnu |
| 11:45–11:55 | 10 min | Lektor provede sloučení, společně ověříme main a historii |

### Vysvětlení základních pojmů

Git zaznamenává verze souborů a historii změn. GitHub je služba, kde repozitář sdílíme a spolupracujeme nad ním. Větev odděluje rozpracovanou změnu. Commit je uložený krok v historii větve. Pull request navrhuje převzetí změny a dává prostor kontrole. Merge znamená sloučení do cílové větve.

### Cvičný obsah

Repozitář obsahuje dokumentaci fiktivní SAP úpravy pro kontrolu vstupních dat. Účastníci nepíší program. Každý opraví nebo doplní jeden krátký Markdown soubor podle konkrétního zadání. Úkoly se navzájem nedotýkají, takže lze procvičit spolupráci bez plánovaných konfliktů.

### Role AI a člověka

AI pomáhá načíst a vysvětlit zadání, navrhnout malou úpravu a zkontrolovat skutečný diff. Člověk kontroluje obsah a ve webu GitHubu sám provede commit a pull request. Kontrolu provede jiný člověk. Sloučení v tomto cvičení řídí lektor.

Předvedení propojení: z ChatGPT nech načíst README.md a jedno zadání v main přes dostupné GitHub propojení. Název účtu a možnost přístupu ověř předem. Pokud nelze načíst přesnou větev nebo nový obsah, účastník vloží odpovídající text či diff ručně a tuto skutečnost uvede.

## Lektorská ukázka úkolu 00

Otevři zadani/00_ukazka.md a soubor docs/scenare/00_ukazka.md. Zadání doplňuje účel krátkého popisu: název Kontrola vstupních dat v SAP, větu o kontrole před uložením a doplnění verze 1.1, autora a data.

1. V GitHubu ukaž název organizace, repozitář, větev main a README. Přes připojení k ChatGPT nech vysvětlit zadání.

2. Z aktuální main vytvoř ve výběru větví větev ukazka/lektor. Zkontroluj, že ji web skutečně zobrazuje.

3. V ChatGPT vlož zadání a současný obsah. Vyžádej malou změnu. Výsledek přečti a porovnej s kritérii.

4. Ve své větvi otevři cílový soubor, zvol úpravu tužkou, vlož zkontrolovaný text a ulož přes Commit changes. Ukaž zprávu a větev commitu.

5. Otevři Pull requests a New pull request. Base nastav na main, compare na ukazka/lektor. Ukaž skutečný diff a popiš změnu i ověření.

6. Jiný účastník otevře Files changed. Porovná výsledek se zadáním a přidá kontrolu. Ukaž rozdíl mezi komentářem, žádostí o úpravy a schválením.

7. Lektor po kontrole sloučí pull request. V main otevři změněný soubor a historii. Změna se v hlavní větvi objeví po sloučení.

### Co říct při ukázce

Před commitem se ptej: Ve které větvi jsem? Před pull requestem: Co přesně se mění? Před sloučením: Kdo změnu zkontroloval a podle čeho? Názvy tlačítek ukaž na skutečném účtu, protože se rozhraní může lišit jazykem a oprávněními.

### Přiřazení účastnických úkolů

Úkol 01 až 09 přiděl vždy právě jednomu člověku; přiřaď mu odpovídající GitHub issue. Každý použije větev cviceni/NN-github-login a upraví jen docs/scenare/NN_*.md podle své karty. Kontrolu přiřaď do kruhu: každý kontroluje následujícího, poslední prvního. Použij skutečný počet účastníků.

## Podpora během cvičení a pokračování

| Situace | Postup lektora |
| --- | --- |
| Repozitář nejde otevřít | Ověř správný GitHub účet, členství, pozvánku a přístup k přesnému repozitáři. Případné firemní přihlášení řeší správce. |
| Chybí možnost editace | Ověř oprávnění a vlastní pracovní větev. Požadavek na fork v tomto cvičení zastav a zkontroluj přidělený přístup. |
| ChatGPT soubor nevidí | Nech doložit přesnou cestu a větev. Pro pokračování vlož obsah ručně, ověření připojení zachyť jako samostatný problém. |
| Pull request neukazuje změnu | Zkontroluj base main, compare vlastní větev, existenci commitu a správný soubor. |
| Kontrola vyžaduje opravu | Autor opraví stejný soubor ve stejné větvi a uloží další commit. Nový pull request nezakládá. |
| Sloučení je blokované | Přečti konkrétní podmínku. Doplň kontrolu nebo požadovaný krok. Neobcházej nastavení repozitáře kvůli tempu workshopu. |
| Vznikl konflikt | Zachovej práci, ukaž příčinu a řeš s lektorem. Nevol automatické přepsání cizí změny. |

### Práce s časem

V 11:35 zkontroluj počet otevřených pull requestů a podle toho soustřeď pomoc. Cílem zůstává dokončení celého postupu. Rychlejší účastníci pomáhají s kontrolou kolegů, další rozšíření přichází až po vlastním dokončení.

Pokud se první nebo druhá část prodlouží, třetí část naváže později. Nezkracuj povinný obsah prostoru a jeho pravidel. Kolem 11:50 zajisti uchování práce a posledních 5 minut věnuj závěru. Příště se pokračuje konkrétním nedokončeným krokem, bez opakování hotových úkolů.

## Příprava prostoru a zdrojové odkazy

### Orientace v existujícím prostoru Xerox

- Project Home a How to Work with This Space: účel, navigace, rozsah dokumentace a pravidla práce.

- 05 Tasks, Risks and Open Questions: úkoly, rizika a chybějící rozhodnutí; vlastník a termín podle skutečné dohody.

Použij existující projektovou strukturu. Stránky nejsou úplnými kopiemi zdrojových souborů; přesné detaily ověřuj v originálu. Cvičnou stránku a konkrétní podklady předem určí lektor. Do GitHub repozitáře patří dodaný fiktivní příklad, odkazy a výukové postupy.
